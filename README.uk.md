# 2mux

[English version](README.md)

2mux поєднує **виконавця Codex (WORKER)** і **рев’юера pi (REVIEWER)** у двох панелях tmux одного проєкту. Фоновий міст автоматично доставляє повідомлення між агентами, зокрема після від’єднання від сесії. Агенти надсилають їх через `2mux send`; копіювати відгуки між панелями не потрібно.

## Документація

Почніть із [посібника користувача](docs/guide.uk.md): встановлення, повний цикл рев’ю та усунення проблем. [Довідник CLI](docs/cli.uk.md) описує всі публічні команди, а [архітектура та розробка](docs/architecture.uk.md) — чергу, міст і набори тестів. Обидві мовні версії зібрано в [індексі документації](docs/README.uk.md).

## Збирання та запуск

Потрібні Linux або macOS, tmux і Go 1.22+ для збирання. Для `--agents` також потрібні CLI `codex` і `pi`, уже налаштовані з вашими обліковими записами та параметрами. Готовому бінарному файлу Go не потрібен.

```sh
go build -o 2mux .
./2mux version
```

Використовуйте абсолютний шлях до бінарного файла або встановіть його в каталог із `PATH`. Запустіть із проєкту, над яким мають працювати агенти:

```sh
cd /шлях/до/проєкту
2mux start --agents
```

У новій сесії це запускає Codex ліворуч і pi праворуч, з інструкціями ролей та абсолютним шляхом до команди надсилання. Завершіть початкові діалоги дозволів CLI, потім введіть завдання в Codex. Виконавець надсилає запит рев’ю після завершення етапу; pi автоматично повертає виправлення або схвалення. Агенти бачать одне робоче дерево; рев’юер отримує інструкцію перевіряти його без редагування. Звичайні налаштування дозволів і облікових записів агентів залишаються чинними.

Для від’єднання натисніть `Ctrl+B`, потім `D`. Щоб підключитися знову, виконайте `2mux` із того самого каталогу. Усередині наявного клієнта tmux команда перемикає його на потрібну сесію. Перестановка панелей і зміна активного вікна не змінюють ролей.

`2mux` без `--agents` створює звичайні оболонки з увімкненим мостом. Для ручного запуску агентів виконайте в їхніх панелях:

```sh
# Панель WORKER
exec codex "$(2mux prompt worker)"

# Панель REVIEWER
exec pi --append-system-prompt "$(2mux prompt reviewer)"
```

`--agents` запускає процеси лише в новій сесії. Під час повторного підключення перевіряє наявність обох агентів і не замінює процеси. Якщо вже є сесія з оболонками, запустіть агентів вручну або збережіть роботу та перестворіть її через `2mux stop`.

## Автоматичні повідомлення

Інструкції ролей містять точну команду з абсолютним шляхом до бінарного файла, `--queue DIR` і `--from ROLE`. Така адресація використовує файловий ввід/вивід і працює, коли shell-інструмент фільтрує `TMUX`, `TMUX_PANE` чи `PATH`. Агент має використовувати згенеровану команду. Оператор у каталозі проєкту може застосувати коротку форму:

```sh
2mux send reviewer - <<'MESSAGE'
Готово до рев’ю: зміну реалізовано.
Файли: bridge.go, queue.go.
Перевірка: go test -race ./... пройшла.
MESSAGE
```

Рев’юер відповідає через `2mux send worker`. Оператор також може передати завдання командою `2mux send worker "Ваше завдання"`. Повідомлення підтримують кілька рядків і UTF-8, до 64 КіБ. Керівні символи термінала відхиляються. Саме виведення `<READY_FOR_REVIEW>` або `<CORRECTION>` нічого не надсилає: транспортом є команда, незалежно від виводу та перемальовування термінала.

Міст зберігає повідомлення перед доставкою, вставляє його як один запит і надсилає клавішу підтвердження. Для цього використано [bracketed paste у tmux](https://man.openbsd.org/tmux.1#paste-buffer). Доставка очікує, якщо в панелі працює оболонка, панель завершилася, перебуває в режимі копіювання, має вимкнений ввід або не містить розпізнаного активного процесу Codex/pi. Керований запуск і ручні приклади з `exec` не залишають оболонки після завершення агента. Власні запити підтвердження CLI потребують вашої дії. Уникайте ручного введення в панель під час надходження повідомлень.

`queued` означає прийняття в локальну чергу. `delivered` означає надсилання в термінал; це **не** доказ того, що модель отримала, зрозуміла або виконала запит. Обробку нових запитів під час роботи агента визначає його CLI.

## Команди

| Команда | Дія |
| --- | --- |
| `2mux` / `2mux start` | Створити сесію чи підключитися; запустити або відновити міст. |
| `2mux start --agents` | У новій сесії запустити Codex + pi з інструкціями ролей. |
| `2mux start --detach` | Запустити без підключення; можна поєднати з `--agents`. |
| `2mux send worker\|reviewer "текст"` | Додати повідомлення в чергу; `-` читає stdin. |
| `2mux prompt worker\|reviewer` | Показати інструкцію з адресою черги поточної запущеної сесії. |
| `2mux status` | Показати панелі, наявність агентів, стан мосту та кількість повідомлень. |
| `2mux messages` | Показати квитанції, помилки та приватний каталог записів. |
| `2mux resolve ID delivered` | Після перевірки агента позначити невизначену доставку як надіслану. |
| `2mux resolve ID retry` | Після перевірки агента повторно поставити невизначене повідомлення в чергу. |
| `2mux stop` | Завершити міст, сесію поточного каталогу та її процеси. |
| `2mux help` / `2mux version` | Показати довідку / версію (`dev` після звичайного збирання). |

## Відновлення та зберігання

Лише один міст може тримати блокування процесу сесії. Повідомлення зберігаються атомарними JSON-записами у приватному тимчасовому каталозі (права `0700`; файли `0600`), шлях до якого показує `status`. Після перезапуску міст продовжує доставку черги без повторення завершених повідомлень. Для кожного адресата зберігається порядок. Недоступність одного агента не блокує інший напрямок.

Запуски та зупинення для того самого канонічного каталогу проєкту серіалізуються, включно з першим створенням сесії. Сталий приватний каталог `/tmp/2mux-control-UID` зберігає файли блокувань проєктів незалежно від `TMPDIR` того, хто викликав команду; текстів повідомлень у ньому немає. Блокування життєвого циклу звільняється перед інтерактивним підключенням.

Якщо міст аварійно завершується під час надсилання або tmux повертає помилку після можливого початку вставлення, квитанція переходить у `uncertain`. Наступні повідомлення цьому адресату очікують. Спершу перевірте агента-одержувача, потім через `resolve` позначте квитанцію доставленою або дозвольте повтор. Невизначене повідомлення ніколи не повторюється мовчки.

`stop` завершує процеси панелей — спершу збережіть їхню роботу. Незалежні служби CLI керуються самим CLI. Записи доставки залишаються для перевірки; видаліть показаний каталог, коли вони більше не потрібні. Кожна нова сесія отримує новий приватний каталог. Записи містять текст обміну; повні транскрипти терміналів, облікові дані та телеметрія не збираються. Тимчасове сховище не є постійним архівом і може очищатися операційною системою.

Назва сесії містить хеш канонічного шляху проєкту. 2mux перевіряє позначку каталогу перед підключенням чи зупиненням і використовує збережені ID панелей. Чужа сесія з конфліктною назвою відхиляється. Відсутня чи завершена панель повідомляється як проблема; інша панель не отримує її роль автоматично. Сесії попередньої версії з оболонками не містять метаданих мосту: збережіть роботу, зупиніть їх і створіть нову сесію.

## Перевірка

```sh
go test -race ./...
go vet ./...
TWOMUX_INTEGRATION=1 go test -race -v ./...
TWOMUX_NATIVE_SMOKE=1 go test -v -run TestInstalledAgentPresence
```

Інтеграційний тест запускається окремо й використовує власний сокет tmux та детерміновані локальні TUI-фікстури. Він перевіряє одночасні перші запуски з оболонками й агентами, цикл виконавець → рев’юер → виправлення → повторне рев’ю → схвалення, багаторядковий UTF-8, роботу без підключення, перестановку панелей, додаткові вікна, відновлення мосту, відсутність дублів, режим копіювання, вимкнений ввід, захист оболонки та належність сесії. Він не викликає моделей чи мережі та не використовує ваші сесії tmux. Окремий smoke-тест запускає встановлені Codex/pi без надсилання запиту моделі й перевіряє розпізнавання процесів. Відповіді справжніх моделей і поведінку черги їхніх CLI потрібно перевіряти з установленими агентами.

Установлена пара Codex/pi також пройшла живий сценарій автоматичного рев’ю файла; дивіться [результати рев’ю](REVIEW.uk.md) та [квитанції](validation/live-review-20260930.json).
